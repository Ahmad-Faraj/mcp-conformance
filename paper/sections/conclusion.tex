The MCP server ecosystem has been measured statically many times, but never by
running it. So we ran it. Every eligible server in the official registry was
installed, launched in a disposable sandbox, and driven through the protocol.

\HandshakeRateCorr{} complete a handshake. The rest crash, hang, or exit without
serving anything at all. Among the servers that do respond, \ErrAsResultRate{}
diverge from the specification's own illustrated error handling in exactly the same
way, and that uniformity says nothing about developers: it is inherited from a
handful of SDK defaults, propagated directly and through third-party wrappers built
on them. A smaller group, \SilentExecRate{}, will run a tool on input their published
schema rejects and return a well-formed answer carrying no sign that the input was
never valid. One asked to scan an integer for unsafe imports reported it clean.

None of this is visible to a static scanner or a registry crawl. All of it matters to
anyone building on the layer. We release the harness and the dataset so the
measurement can be repeated, extended to remote and credentialed servers, and run by
authors against their own servers before they publish. The behaviour is set at the
SDK layer rather than by thousands of independent choices, which is the discouraging
finding and also the encouraging one: it can be corrected there too.
