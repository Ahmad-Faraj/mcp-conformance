\label{sec:threats}

\paragraph{Construct validity.}
Our verdicts operationalize ``conformance,'' and a poorly chosen operationalization
could over- or under-count. We mitigate this in three ways. First, we grade each
server against the protocol version it \emph{negotiates}, not the latest
specification, so a server is never penalized for a requirement that postdates its
target revision. Second, we distinguish normative requirements from illustrative
ones: the most prevalent divergence we report (unknown-tool responses) is graded as
a distinct \textsf{error-as-result} category rather than a failure, precisely
because the specification expresses it in prose and an example rather than an
RFC-2119 keyword. Third, we calibrated the harness against the official reference
servers before the study and confirmed it reproduces their known-good behavior on
every check except the SDK-level divergence we set out to measure.

\paragraph{Internal validity.}
The census was measured in the single-phase condition, with the network available
during both install and probe (Section~\ref{sec:method-env}). This avoids penalizing
a server that legitimately contacts the network during initialization, but it does
not remove server-side outbound calls as a confounder. The exposure is concentrated
in one check. For \textsf{tools-call-invalid-args} we accept an \texttt{isError}
result as evidence that the server rejected the ill-typed argument; an
\texttt{isError} produced instead by an unrelated runtime or network failure is
indistinguishable to the harness, and would be counted as argument checking that did
not in fact occur. The reported rate of silent type non-enforcement is therefore a
\emph{lower bound}. The lifecycle, tool-listing, error-handling, malformed-input and
stdout-purity checks are local protocol behaviors and are not exposed to this
confound. A network-isolated replication would tighten the argument-checking result,
and the harness supports that condition directly. Sandbox heterogeneity across
language runtimes is a further
source of noise, which we bound by pinning base images and package versions and by
stamping every result with the harness commit that produced it.

\paragraph{External validity.}
Our population is self-contained, locally-installable servers distributed on npm and
PyPI using the stdio transport. This excludes remote-only servers (which we cannot
execute without provisioning hosted infrastructure) and servers requiring
credentials (which we exclude for both ethics and reproducibility). We report the
size of each excluded class explicitly and confine all rates to the stated frame;
we do not claim they generalize to remote or credentialed servers, whose conformance
is important future work. Because agent clients overwhelmingly launch local stdio
servers, we argue this population is the most consequential one to characterize
first.

\paragraph{Completeness.}
We probe the entire eligible frame---all \Nprobed{} servers (\Nresponders{}
responding)---so the study is a complete census of the eligible population rather
than a sample. The confidence intervals we report throughout therefore reflect
residual measurement noise (e.g.\ server-side nondeterminism) rather than sampling
error, and should be read together with the publisher-clustering caveat below. The
conformance findings (RQ2--RQ4) are near-universal, and the runnability funnel (RQ1)
rests on the full population rather than an estimate.

\paragraph{Publisher clustering.}
The \Nprobed{} servers in our frame come from only \Npublishers{} distinct registry
namespaces, and the distribution is heavy-tailed: the largest single publisher
accounts for \TopPublisherN{} servers (\TopPublisherPct{} of the census) and the ten
largest for \TopTenPct{}. Servers from one publisher frequently share a template and
behave near-identically, so they are not independent observations, and the Wilson
intervals we report---which assume independent trials---understate the true
uncertainty. To bound the effect, we recompute each headline rate on a
publisher-deduplicated subset retaining one server per namespace (\NuniqPub{}
servers). Every estimate moves by a few points and no conclusion changes: handshake
yield \HandshakeRatePub{} (against \HandshakeRate{} for the full census),
error-as-result \ErrAsResultRatePub{} (against \ErrAsResultRate{}), and silent type
non-enforcement \NoTypecheckRatePub{} (against \NoTypecheckRate{}). The
single largest publisher is atypical in runnability (a \(26.2\%\) handshake yield
against \(60.4\%\) overall), and alone depresses the census figure by \(1.8\)
percentage points. We report the full-census figures as our primary result, because the
census rather than a sample of publishers is the object of study, and the
publisher-deduplicated figures as the robustness check.

\paragraph{Interrupted probes.}
A small fraction ($\le 0.4\%$) of probes were interrupted by the automated disk-guard
that reclaims host space near capacity (Section~\ref{sec:method-env}). These are
recorded conservatively as non-handshaking; because the interruption is a property of
the harness environment and not of the server, and because it is uncorrelated with
any server property, it does not bias conformance rates (computed over responding
servers) and can only very slightly depress the handshake yield. The released dataset
flags these runs for audit.

\paragraph{Reproducibility.}
Every number in this paper is regenerable from released raw JSON-RPC transcripts and
the pinned harness commit. The sampling seed, registry snapshot, base images, and
package versions are all recorded. Because the registry is a moving target, we
report the crawl date and treat the snapshot, not the live registry, as the object
of study.
